00 · the mental model

A neural net is just a function you fit to data.

Strip away the hype and a neural network is a big parameterized function f(x; θ) → y. You don't write the logic — you fit the parameters θ until the function does what you want.

As an engineer, you already know this shape. Think of it as three loops:

  • Inference = a request handler. Input comes in, flows through a fixed set of matrix multiplies, an answer comes out. Deterministic, fast, stateless.
  • Training = an optimization loop / CI job. Run inputs through, measure how wrong the output is (the loss), nudge every parameter slightly toward "less wrong," repeat millions of times.
  • The parameters (θ) = the build artifact. A trained model is just a few million-to-billion floating-point numbers — the "weights." Shipping a model is shipping that blob.
SDE LENS

The whole field is one idea repeated: stack simple differentiable operations, then use calculus to automatically tune their knobs against a loss. CNNs, GNNs, Transformers — they're all the same training loop with different "layers" (different ways of mixing information). Once you get the loop, every architecture is a variation on how information is allowed to flow.

That's the entire arc of this guide. We'll build the loop from a single neuron (§1–2), then tour the three big ways people wire neurons together depending on the data: grids/images → CNNs (§3), graphs/relationships → GNNs (§4), and sequences/text → attention & Transformers (§5). Finally we'll assemble those into RAG (§6), the pattern behind most production LLM apps.

01 · neurons & networks

One neuron is a weighted sum with a switch.

A neuron takes inputs, multiplies each by a learned weight, adds them up plus a bias, and squashes the result through an activation function. That's the atom. Everything else is wiring.

Formally, for inputs x and weights w: output = activation(w·x + b). The dot product w·x is "how much do I care about each input"; the bias b shifts the threshold; the activation adds the non-linearity that lets stacks of neurons represent curves, not just straight lines.

Without a non-linear activation, stacking layers is pointless — a chain of matrix multiplies collapses into a single matrix. The activation is what makes "deep" meaningful. Here are the common ones; drag to see their shapes:

An MLP layer is literally y = activation(W @ x + b) — a GEMM (matrix multiply) plus an elementwise op. This is why GPUs matter: training is billions of these multiplies, and they parallelize perfectly. "Bigger model" mostly means "bigger matrices."

02 · how they learn

Learning = rolling downhill on a loss surface.

Training has two halves: backpropagation computes which direction reduces error for every weight, and gradient descent takes a small step that way. Repeat. That's it.

Picture the loss as a landscape where altitude = "how wrong the model is," and the coordinates are the weights. The gradient is the slope — the steepest-uphill direction. So we step the opposite way (downhill) by a small amount called the learning rate. Backprop is just the chain rule from calculus, run efficiently backward through the layers to get that slope for every weight at once.

The learning rate is the one knob everyone fights with. Too small: glacial. Too big: you overshoot the valley and bounce out. Click anywhere on the surface to drop a marble and watch it descend:

SDE LENS

You never hand-derive these gradients. Frameworks (PyTorch, JAX) build a computation graph of every operation and auto-differentiate it — same idea as a build dependency graph, but it propagates derivatives backward instead of artifacts forward. Your job is to define the forward pass; the gradient comes free.

04 · CNNs · vision

CNNs slide one tiny filter over the whole image.

An image is a grid where nearby pixels are related. A Convolutional Neural Network exploits that: instead of one giant weight per pixel, it learns a small kernel (e.g. 3×3) and slides it across every position, reusing the same weights everywhere.

Each kernel is a little pattern detector. Slide it over the image computing a weighted sum at each spot, and you get a feature map — a heatmap of "where did this pattern appear." Early layers learn edges and textures; stacking them builds up to shapes, then objects. Two ideas make this cheap and powerful:

  • Parameter sharing — the same 9 numbers detect a vertical edge anywhere in the image. Massively fewer weights than a dense layer (a 3×3 kernel is 9 numbers; a dense layer over a 224×224 image is ~50k per neuron).
  • Translation invariance — a cat in the corner fires the same detectors as a cat in the center, so the network doesn't relearn "cat" for every position.

05 · GNNs · graphs

GNNs let nodes gossip with their neighbors.

Lots of data isn't a grid — it's a graph: social networks, dependency trees, molecules, knowledge bases, your service mesh. A Graph Neural Network learns by having each node repeatedly aggregate messages from its neighbors.

One GNN layer = one round of message passing: every node looks at its neighbors, combines their feature vectors (sum/mean/max), and updates itself. After k layers, each node has absorbed information from everything within k hops. Stacking layers grows each node's "receptive field" outward through the graph.

SDE LENS

If you've implemented a gossip protocol or epidemic broadcast, you already understand message passing. Each round, state diffuses one hop further. A GNN just makes the aggregation step learnable — the network learns how to weight and combine neighbor messages instead of plain averaging.

06 · embeddings & attention

Meaning is a vector. Attention is who-looks-at-whom.

Text first becomes embeddings: every token maps to a vector, positioned so that similar meanings sit close together. Then attention — the engine of Transformers and LLMs — lets each token pull information from the tokens most relevant to it.

Embeddings turn words into geometry. "King" and "queen" land near each other; "GPU" lands near "compute." Distance ≈ semantic similarity, usually measured by cosine similarity (the angle between vectors). This is the foundation for search, recommendations, and the retrieval in RAG. Hover or tap a word to see its nearest neighbors:

Nearest neighbors appear here.

Self-attention is the breakthrough behind Transformers. Each token emits a query ("what am I looking for?") and a key ("what do I offer?"). Compare every query to every key and you get an attention matrix: how much each token should listen to each other token. The token then pulls a weighted blend of all values. Crucially, every token does this in parallel — no sequential bottleneck, which is why Transformers train so well on GPUs.

SDE LENS

Attention is a soft, content-addressable lookup — like a hashmap where instead of one exact key match you get a weighted blend across all keys by similarity. A Transformer is just stacks of (attention → MLP) blocks. Scale that up on internet-scale text and you get an LLM.

07 · RAG · retrieval-augmented generation

RAG = give the LLM an open-book exam.

An LLM only knows what was in its training data, frozen at some date, and it can't cite sources. RAG fixes both: before answering, retrieve relevant chunks from your documents and paste them into the prompt. The model answers from the page, not from memory.

The pipeline has two phases. Indexing (offline): split your docs into chunks, embed each chunk into a vector (§5), store them in a vector database. Query time (online): embed the user's question, find the nearest chunks by similarity, stuff those into the prompt as context, and let the LLM generate a grounded answer.

SDE LENS

RAG is a read-through cache for knowledge. The vector store is your index; embedding is the hash function that maps "meaning" to a lookup key; top-k retrieval is the query. The LLM is a smart formatter on top of the rows you fetched. You scale and update knowledge by updating the index — no retraining.
